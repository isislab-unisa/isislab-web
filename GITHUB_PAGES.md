# Deploying ISISLab to GitHub Pages — v10.1 fix

## Why the v10 site returned 404 for styles, scripts and images

The theme files **were included** in the ZIP, but `_config.yml` used an empty `baseurl`. That is correct at `http://localhost:4000/`, but not for a GitHub Pages *project site* at `https://USERNAME.github.io/REPOSITORY/`. Without the `/REPOSITORY` prefix, requests for CSS, JavaScript, and logos went to the wrong location. A second issue is that image mappings generated by a local WordPress import may refer to image files that were not committed to the repository.

v10.1 adds a GitHub Actions workflow which obtains `base_path` from `actions/configure-pages` automatically. It builds Jekyll with that prefix, checks the required theme files and repairs remaining missing local editorial image URLs and validates every local image/CSS/JS URL in the generated HTML before deployment. It also replaces references to non-committed WordPress images with bundled SVG placeholders, avoiding broken image tiles (the missing original image files are *not* created or invented).

## Deploy the project

1. Extract the ZIP and copy the **contents of `isislab-jekyll/`** (not the enclosing directory) to the **root of your GitHub repository**. You should see `_config.yml`, `index.html`, `assets/`, `_layouts/`, `scripts/` and `.github/workflows/pages.yml` at repository root.
2. Commit the whole project, including `.github/`, the four CSS files, the two JavaScript files, the PNG logo, and any downloaded media:

   ```bash
   git add -A
   git commit -m 'Fix ISISLab GitHub Pages asset paths'
   git push
   ```

3. In **GitHub → Settings → Pages**, set **Build and deployment → Source → GitHub Actions** (instead of "Deploy from a branch").
4. In the **Actions** tab, open **Build and deploy ISISLab Jekyll site** and check the green build and deploy steps. The build fails with a clear report if a referenced local asset is missing.
5. Open the URL shown by GitHub Pages, then hard-refresh the browser to clear old cached CSS/JS. It will look like `https://USERNAME.github.io/REPOSITORY/` for a project site, or `https://USERNAME.github.io/` for a user site.

Both site types are supported automatically by the same workflow. Custom domains also work because the workflow receives the actual GitHub Pages base path. **Do not hardcode a repository name into every HTML template.**

### Verify the assets

For a project site hosted at `https://USERNAME.github.io/REPOSITORY/` these URLs should return the file, not a 404:

- `https://USERNAME.github.io/REPOSITORY/assets/css/refinements-v10.css`
- `https://USERNAME.github.io/REPOSITORY/assets/css/reference-fidelity.css`
- `https://USERNAME.github.io/REPOSITORY/assets/css/elegant.css`
- `https://USERNAME.github.io/REPOSITORY/assets/js/site.js`
- `https://USERNAME.github.io/REPOSITORY/assets/js/physics-balls.js`
- `https://USERNAME.github.io/REPOSITORY/assets/img/isislab-brand-horizontal.png`
- `https://USERNAME.github.io/REPOSITORY/assets/img/news-placeholder.svg`

Replace `USERNAME` and `REPOSITORY` with your actual values.

### News and press thumbnails

Original press/news images are **not** bundled in v10.1 (previous attempts to access the source server failed). The ZIP includes small SVG placeholder images that are guaranteed to exist. If you import/download original media, commit **the actual** `assets/img/news/` and `assets/img/press/` files together with `_data/media_local.yml` and `_data/media_thumbs.yml`. The deploy preparation step removes mappings whose files are not present in the Git checkout so the built website falls back to the bundled placeholders.

You can run checks locally after installing Jekyll:

```bash
python3 -m pip install PyYAML
python3 scripts/prepare_deploy.py
bundle install
bundle exec jekyll build --baseurl /REPOSITORY
python3 scripts/repair_built_images.py --baseurl /REPOSITORY
python3 scripts/check_built_site.py --baseurl /REPOSITORY
```

Use an empty `--baseurl ''` for user sites/custom domains.

### What about `share-modal.js`?

`share-modal.js` is **not** shipped or referenced by the ISISLab Jekyll source. Its JavaScript exception appears to come from an extension or external script. If it persists after deployment, check the script URL in DevTools and reproduce in a private window with browser extensions disabled.

### Without GitHub Actions

If you are required to publish "Deploy from a branch" instead, manually set `baseurl: "/REPOSITORY"` in `_config.yml` for a project site and publish the Jekyll **build output** with every asset included. The bundled Actions workflow is the recommended and tested-path configuration, since it prevents incorrect prefixes when repository name/domain changes.
